# Anjo-Core: Architecture & Technical Deep Dive

Welcome to the technical overview of **Anjo-Core**. This document explains the underlying architecture, the concept of operational *Ataraxia*, and how the 37 autonomous agents work together to enforce a zero-trust DevSecOps pipeline.

## 1. The Philosophy of *Ataraxia*
In classical philosophy, *Ataraxia* means a state of serene calmness and freedom from emotional disturbance. In the context of Anjo-Core, it translates to **operational stillness**. 
When code is generated by AI at unprecedented speeds, human review becomes a bottleneck. Anjo-Core does not merely "test" code; it actively governs the environment to maintain this stillness, ensuring that only structurally sound and cryptographically verified code can enter the main branch.

## 3. Core Components

### A. Automated Requirement Parsing (MCP Integration)
Instead of manually writing test cases, Anjo-Core utilizes the **Model Context Protocol (MCP)**.
* **Input:** Functional requirements written in Excel or YAML.
* **Process:** Multiple LLMs read the specifications and use a consensus mechanism to prevent hallucinations.
* **Output:** Dynamically generated, highly restrictive test suites tailored to the specific commit.

### B. The Agentic Swarm (37 Specialized Agents)
The system distributes validation tasks across 37 independent, specialized agents. Each agent has a single, isolated responsibility to prevent systemic blindness. 
Examples of agent roles include:
* **Semantic Drift Detector:** Ensures AI-generated code does not deviate from the original business logic.
* **Canary Data Watchdog:** Scans for leaked credentials, hardcoded secrets, or injected malicious payloads.
* **Dependency Auditor:** Verifies the cryptographic signatures of all imported libraries.

### C. The Samson Option (Fail-Closed Circuit)
Passive QA frameworks often log an error and continue. Anjo-Core is designed to be **fail-closed**. 
If a critical structural anomaly is detected (e.g., a memory leak pattern, unauthorized network call, or security vulnerability), the protocol triggers *The Samson Option*. This is a local kill-switch that instantly isolates the runtime environment, purges all tainted state, and forcefully terminates the pipeline before any merge can occur.

### D. Cryptographic Enclaves & Auditing
Security and compliance are non-negotiable.
* **TEE Runtime:** All critical validations occur within simulated Trusted Execution Environments to prevent memory tampering during tests.
* **Zero-Knowledge Proofs (ZKP):** The system generates a cryptographic proof that the code was tested against the exact specifications without revealing the proprietary test logic itself.
* **Immutable Logs:** Standardized JUnit XML logs are cryptographically signed, ensuring they cannot be altered post-execution.
